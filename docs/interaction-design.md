# AI が書いている途中で考えを返せるボード

2026年11月21日時点の設計メモ。試作を触ったときの観察と、次に試したい設計を記録する。

「アプリの名前を考えたい」と書いた人が、最初から命名の条件を言えるとは限らない。今回の試作では、Codex が書いた文の空欄に「誰かと一緒に考える心強さ」を選ぶと、その感覚を表す名前として「となり案」が返ってきた。私がこのボードで大事にしたいのは、その一語を選んだことで、続く文章が自分の判断を受けて変わったと分かる瞬間だ。

## 最初の付箋で見えたこと

初版では、入力した文、Codex の書き出し、問いが、同じ黄色い付箋に同じ調子で並んだ。ユーザーの感想は「何かレスがあったのかどうかという観点が全くわからない」だった。生成にかかった秒数を表示しても、どこからが新しく届いた言葉なのかは読み取れない。新版では原文を残し、その下に Codex の文章を置いた。応答の出所は示せた。複数の付箋を行き来する人が、新着にも自然に気づけるかはまだ確かめていない。

別の付箋には「AIからの返事にテキスト選択をして追い質問とかしたい」と書かれていた。たとえば「となり案」の三文字を選んで「もう少し道具らしい響きにできる？」と尋ねられれば、対象を説明し直さずに済む。最初の応答を読んだあとも、その一節から考えを続けられる。この操作はまだ実装していない。

## 動画から持ち帰った二つの操作

Bruce Liu の動画の前半では、日本への家族旅行について入力している最中に、子どもの年齢や興味、行き先を調整できる。何を前提に旅程が作られるかが、送信前に見えている。今の試作で入力中に出る「生成の方向」は、ローカルの規則で選んだ文章全体への候補だ。「子ども」のような個々の語に結び付いた解釈を見せるところまでは届いていない。[投稿とデモ動画](https://fxtwitter.com/liu_xingyu/status/2121015724374397183)

後半では、誕生日の夕食について書かれた一文に、人数、好物、乾杯の挨拶の調子が空欄として残る。選ぶたびにその場の文章が埋まり、最後に選択を反映した献立が続く。試作に取り込んだのはこちらの一往復だ。Codex の文中に空欄を一つ置き、候補でも自由入力でも埋められるようにした。空欄を置く価値があるのは、選び方でその先の内容が変わるときだと思う。

## 原文と返事をどこに置くか

Figma の3案は、同じ入力に対して候補を開いた瞬間を描いている。今回合意している意匠の方針は、アイコンに Lucide を使い、余分な補助ラベルを避け、配置で関係を伝えること。どの案を採るかは未決定だ。

| 案 | 試したいこと | 気になること |
| --- | --- | --- |
| [付箋の中で選ぶ](https://www.figma.com/design/bUuJilPsbZWsJIw9gnZC0z/intra-turn-board?node-id=3-2) | 一枚を上から読めば、入力から選択までたどれるか。 | 長くなると、下に届いた返事を見落としそうだ。 |
| [応答を隣に置く](https://www.figma.com/design/bUuJilPsbZWsJIw9gnZC0z/intra-turn-board?node-id=3-23) | 原文の隣に新しいカードが現れるだけで、返事の到着と相手が分かるか。 | すでに隣に別の付箋があるとき、置き場所が競合する。 |
| [本文の余白で選ぶ](https://www.figma.com/design/bUuJilPsbZWsJIw9gnZC0z/intra-turn-board?node-id=3-45) | 本文を読みながら、その横で候補を比べられるか。 | 表示幅が狭いと、空欄と候補を同時に見にくい。 |

私なら次は「応答を隣に置く」を試す。付箋を二枚使い、一枚目で生成を始めたあと、二枚目に書き続ける。返事が届いてもフォーカスと入力中の文章を保てるか。その状態で、どの付箋への返事かを説明なしで見つけ、空欄を埋められるか。この一連の操作なら、静止画だけでは分からない「作業を続けながら応答に気づけるか」を確かめられる。

その結果を見てから、同じ配置で追い質問も扱えるかを考えたい。返事が増えるほど親子関係を追いにくくなるなら、選んだ一節のそばに短く展開する方法もある。付箋という見た目を残すかどうかも、この操作を試したあとで判断できる。
